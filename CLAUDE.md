# Kit PvP

## Origin
This repo started as the empty Bowling Roll / boat-race base (player, physics, camera, avatar, sky, Bloxity SDK wrapper) and is now **Kit PvP**. Its git remote still points at the old boat-race repo: do not push there; create a new public repo when publishing (root CLAUDE.md). The Colyseus backend in `../Bowling-roll-backend` is not used yet.

## Current state: lobby only
The voxel sky-island lobby is built. **The arena is not**: dropping through the hole in the pit fades to "Arena coming soon" and returns you to spawn (`enterArena()` in `main.js`). That function is the hook for the arena: load/teleport into it there. `ARENA.enterY` (config) is the depth that triggers it; the shaft is open to the sky below the island, so an arena placed under the island will be visible through the hole.

Three.js (vanilla) + Vite + Rapier. Everything is procedural: block textures, item pixel art, character skins and all sounds (WebAudio synthesis, `src/audio.js`); the only imported model is the Bloxity rig `public/avatars/player.glb`. Font: Fredoka.

- `npm run dev` / `npm run build`. Preview config `kitpvp` in `.claude/launch.json` runs vite on port 5241 with `VITE_DEV_MODE=true` (no Bloxity SDK/CDN).
- All tunables in `src/config.js`: identity, `SPAWN`, `PHYSICS` (MC-like 1 m blocks: walk 5.6, jump clears one block, autostep 0.55 for slabs/stairs), `LOBBY` (island radius, pit ellipse + terraces + hole, bot count), `ARENA`, `CRATES`, `DAILY_REWARD`, `KITS`, `SHOP_ITEMS`, `LOOKS`, `xpForLevel`, plus the look/camera/rig settings from the base.
- **Currency rule**: everything is bought with Gold (earned in the arena, from crates and the daily reward). No premium currency anywhere; the reference's "TOP ROBUX" board is "TOP GOLD".

## Files (`src/`)
- `main.js`: boot (SDK -> renderer -> Rapier -> lighting -> lobby -> player -> HUD -> avatar -> loop). Interaction (crosshair ray vs interactable boxes, E key, right click, touch taps, proximity prompt), crate opening + rewards, footsteps/jump/land sounds per surface, fall wind, the arena drop. `__game` (dev) exposes player, scene, lobby, hud, state, teleport, setMode, openCrate, sfx.
- **Voxels** `voxel/`: `blocktex.js` 16x16 pixel painters for every block (Nearest mag, mipmapped min). `voxels.js` block registry (cube, slab, slab_top, stair with facing, fence, cross plants; opaque/cutout/plant), sparse `VoxelWorld`, mesher (face culling + per-vertex AO, one geometry group per texture) and greedy cuboid colliders. **No Z-fighting by construction**: faces against full opaque cubes are dropped, partial shapes skip their shared faces, overlays are strictly larger boxes. Keep it that way: never put two visible faces in one plane; offset decals/signs from walls.
- **Lobby** `lobby/`: `layout.js` places every block (island with noisy edge, grass rim + hummocks, funnel pit = dark-wood stair rim then light stone terraces down to the open shaft, white-canopy stall, cabin, crate plaza + shed, leaderboard house with ice path, cobble arch, campfire corner, lamp posts, oak/dark-oak trees, flora, floating rocks) and returns anchors. `index.js` builds props/NPCs/effects from the anchors and runs per-frame emitters. `models.js` extruded pixel items, chests (hinged lid; ranked = obsidian + glowing seam), lanterns, campfire + flame shader. `characters.js` blocky humanoids (64x64 painted skins, outer layer, iron/dark/gold armor, held item, outline highlight, name tags, walk/idle/head-look/swing). `holograms.js` welcome text, leaderboards, crate labels. `fx.js` point-particle engine, crate beams, blocky clouds, floating rocks. `bots.js` wandering lobby players (path-checked against the voxels, kinematic capsules, join/leave feed). `pixelart.js` item + HUD icon art.
- **HUD** `hud/`: menu buttons K kits / B shop / M looks / L reward / O opts (alerts "!"), scoreboard, armor/hearts/level/hunger, XP bar, hotbar (1-9), prompt, feed, toasts, reward pop-up, arena fade, and all menu windows (kits, shop, looks, daily reward, options, crate, duels). Layout classes: `.compact` (short/narrow landscape: menu row top-right), `.portrait` (menu column right, no scoreboard), `.touch`; `--top-safe` comes from `bloxity.onReservedAreas`.
- `state.js` local save (localStorage, wrapped): gold, level/xp, stats, owned kits/looks, hotbar, daily streak, settings. `crates.js` loot tables + roll. `viewmodel.js` first-person held item (drawn last after a depth clear). `audio.js` synthesized SFX (footsteps per surface, UI, coins, crate open, NPC voice, swing, fall wind) + ambience (wind, leaves, birds/crickets) + positional loops (campfire, beams, shaft).
- Base modules unchanged in role: `player.js`, `camera.js`, `modes.js` (starts in first person), `input.js`, `touch.js`, `physics.js`, `lighting.js` (lamp bulbs glow by day too), `postfx.js`, `propkit.js`, `textures.js`, `bake.js`, `avatar/`, `bloxity.js`.
- Controls: WASD, Shift sprint, Space jump, mouse look (click grabs cursor), left click swing, right click / E interact, 1-9 hotbar, K B M L O menus, V first/third person, N day/night, R respawn, Esc closes a menu then opens the portal menu. Never bind P.
- Performance: point lights are expensive on integrated GPUs; the lobby keeps 3 (campfire + 2 lamp posts). Only base skin layers cast shadows.
- Boxity layout: Boxity draws the toolbar + chat top-left; the HUD stays out of those rectangles.

## Mobile & responsive (required for every change)
The game must play on phones and tablets (portrait and landscape) as well as desktop. Treat a feature as unfinished until it works on touch and on a small screen.
- **Input**: every action needs a touch path, not just a key. Use Pointer Events (`pointerdown/move/up`, check `e.pointerType`), never mouse-only events. Layout (implemented in `src/touch.js`): left-thumb virtual joystick -> `inputState.move`, right-side drag -> `inputState.look`, on-screen buttons for jump/sprint/mode/etc., pinch -> `inputState.zoom`. Everything still feeds `inputState` in `src/input.js` so game code stays input-agnostic. Pointer lock does not exist on touch; never rely on it.
- **Detection**: decide touch UI with `matchMedia('(pointer: coarse)')` / `navigator.maxTouchPoints`, not the user agent. Show touch controls only on coarse pointers; a device can have both.
- **Layout/UI**: HUD and menus use relative units (`%`, `vw/vh`, `dvh`, `clamp()`) and flexbox/grid, no fixed pixel layouts. Tap targets >= 44px. Respect notches with `env(safe-area-inset-*)` (viewport already has `viewport-fit=cover`). Text readable at 360px width. No hover-only interactions. Add `touch-action: none` on the canvas and game controls so the browser does not scroll/zoom.
- **Resize/orientation**: anything sized to the screen (camera aspect, renderer, HUD) must react to `resize` (covers orientation changes). Use `visualViewport` where the on-screen keyboard or browser bars matter.
- **Performance**: mobile GPUs are weak. Respect the `graphics_quality` presets in `src/config.js` (cap DPR, shadow map size, draw distance); default to a lower preset on coarse-pointer devices. Avoid per-frame allocations; keep draw calls and texture sizes low.
- **Testing**: check every UI/input change at a phone viewport (e.g. 375x812 and landscape 812x375) with touch emulation, plus desktop, before calling it done.
