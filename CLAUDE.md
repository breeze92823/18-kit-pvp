# Kit PvP

## Origin
This repo started as the empty Bowling Roll / boat-race base (player, physics, camera, avatar, sky, Bloxity SDK wrapper) and is now **Kit PvP**. Its git remote is `breeze92823/18-kit-pvp` (public). The Colyseus backend in `../Bowling-roll-backend` runs the online room (`kitpvp`): presence, combat relay, saves for signed-in players, leaderboards and duels.

## Current rules (these override older wording further down)
- **Progress is saved only on the backend.** No localStorage: `state.js` is in-memory, `sync.js` sends every change (all of `state`, volumes included) and the server's `progress` replaces it on joining (`noProgress new` uploads what was earned so far this page). A guest, or a session that cannot reach the server, keeps progress for the page only.
- **The game's Boxity id is `18-kit-pvp`** (`GAME_SLUG` in config.js = the repos' `LEGION_GAME_ID` = bloxity.io/g/18-kit-pvp). `kit-pvp` is ANOTHER game: using it sent the matchmaker, room directory, boards and token checks to that game (no Open Rooms, boards or in-game player list for ours). Roster players are also reported with `game.playerJoined/playerInRoom` (friend toasts).
- **There are no bots.** No lobby players, no arena bots, no Duels practice bot: the arena and duels are real players only (a lone player fights nobody). `arena/bots.js` survives only as the engine for the Necromancer's zombies (summons, `target: 0` fighters), simulated by the host / the duel's local manager. Mentions of bots, `COMBAT.bots.count`, `NET.minBots`, `lobby/bots.js` or Duels practice below are history.

## Boxity platform features (all in `src/bloxity.js` + `main.js`; decisions in `BLOXITY_CODE_METADATA.md`)
Everything is optional at runtime (no SDK = the game plays on). Not included on purpose: the Game Store (it sells for Gems; see the currency rule).
- **Death screen**: `die()` -> `beginDeathScreen()` (main.js): `bloxity.showDeathScreen()`, the game's own Respawn button (`hud.setRespawn`) shows Boxity's countdown and calls `death.respawn()`; no timer of our own (R presses the button, the portal's Reset Character is instant). Duel round losses are not deaths.
- **Ads**: `onAdBreak` freezes the loop (the clock is rewound so timers don't run) and `sfx.setMuted`; screens `panel` / `results` / `gameplay` are declared from `config.js AD_SCREENS` and reported by `updateAdScreen`; the Shop window's "Watch an ad" button (`ads` in main.js) = rewarded `bonus-gold`, granted only after the server verified the token (`adReward` / `adRewardResult`, offline = the SDK's `completed`).
- **Emotes**: `registerFeature('emotes')` at init, `play_emote` -> `avatar/emotes.js` (clips from `{apiUrl}/v1/avatar/emotes` on the rig, blended 0.1 s, stops on movement; first person switches to third while it plays), relayed as `emote { id }` and played as the REAL clip on the remote player's own rig (`remotePlayers.emote(sessionId, id)`).
- **Remote players' Bloxity look**: each client sends its look as roster `avatar` (JSON `{ e: equipped ids, p: proportions }` from `avatar/look.js serializeLook`, `''` for guests = stock rig) in the join options and as `setAvatar` on every change (net.js, debounced); the server only caps its length. `remotePlayers.js` validates it (`parseLook`: known fields, CDN-shaped ids, clamped proportions), draws every roster player on the player.glb rig with the same `attachEquippedAccessories`/`applyProportions` pipeline as the local avatar (plain rig first, dressed one swaps in), a PlayerAnimator for locomotion, arm poses over it (`PlayerRig.poseBone`: swing / bow draw / block), the kit weapon + shield on gear anchors under the arm bones, own `EmotePlayer`. Kit armor is not drawn. Dev: `__remote.fake([{ id, name, x, y, z, avatar }])` draws pretend players.
- **Chat bubbles**: `chat.onMessage` -> `SDK.chat.attachBubble` over the sender (remote players are found by the roster's `uid` = Boxity id; your own bubble only in third person).
- **Leaderboards**: `BOARDS` in config.js (must equal the backend's `src/boxity/boards.ts`) are declared with `leaderboard.define()`; the SERVER submits scores. Stats, badges and the room directory are backend-only; `badges.onEarned` adds a feed line.
- **Rooms / party / CrazyGames**: hosted + matchmaker = party and Play with friends are automatic (SDK script tag before the game, `net.resolveEndpoint`, room `maxClients` 20). `updateRoom` reports the BARE Colyseus room id (the relay half is per-player, so two players in one room would otherwise report different ids and the Esc menu's "In this server" list would stay empty); `?roomId=` joins that room (`locateRoom`); a sign-in mid-game rejoins the same room by id before falling back to matchmaking (`net.js`). Never bind P, no own fullscreen button.

## Kit progression for new players (overrides older kit wording below)
- **50 kits** (`KIT_TABLE` in config.js, its order = the Kits screen's Default sort). Every kit up to level 11 has an F ability, so a new player's ability button is never empty: Swordsman Lunge (a `dash` renamed via `ability.name`/`icon`, `abilityInfo()` in abilities.js), Archer `volley`, Bouncer Bounce Blast (`slam` with `kb`/`up`), Glider `gust` (cone push), Spring `leap` (big jump, landing slam: `effects.updateLeaps` waits for `owner.grounded`; `you.grounded` getter). New early kits: Spark (L3, `onHit.lightning` every 4th hit with `lightningDmg`, ability `zap` = lightning on the enemy you look at), Wolf Tamer (L5, `zombies` ability with `kind: 'wolf'`: `buildWolf()` in lobby/characters.js, same part api as `buildCharacter`; bots.js `WOLF_BITE`, `b.wolf`, the snapshot's kit slot = 'wolf' for puppets; backend `summon` relays `kind`), Firework (L7, `rocket` jump + star burst), Blinker (L9, `blink` teleport, never through walls), Slime (L10, thrown `slimeball`). Showy kits moved early (Stormcaller 12, Samurai 15, Necromancer 25, Engineer 30); quiet passive kits later; Champion is 126.
- **Ultimate** (`ULTIMATE` in config): a per-life meter filled by damage you deal (`chargeUlt` in combat.js: your hits, relayed hits on our estimate, `takenMul` of damage taken, `killBonus`), full = `charge`. Q (desktop, `cb-ult` widget left of the ability) / the round touch ULT button (`ultButton` in touch.js, left of the ability) fires the weapon family's move: sword Whirlwind (`effects.whirlwind`, replayed as `fx whirl`), bow Arrow Rain (`arrowRain` at the crosshair's ground point; real arrows, relayed like any arrow), axe Earthquake / stick Shockwave (`slam` + `slow`), fists Flurry. Reset by `equip()` (every life, every duel round).
- **Kit mastery** (`MASTERY`, `state.mastery` kit -> kills, `addMastery` in `rewardKill`): Bronze 10 / Silver 30 / Gold 75 / Diamond 150 kills; each tier adds Gold per kill and a cosmetic in the kit colour: kit-coloured kill burst (`effects.fx.killBurst`, replayed as `fx killfx`), sparkling swing trail (`fx.swingTrail`; every charged kit swing draws a plain trail), glowing weapon (`viewmodel.setGlow`), diamond aura. Kits screen: stars on owned rows, progress bar in the info box.
- **Borrowing kits** (`KIT_TRIAL`, state.js `borrow` { id, kind: trial | rent, paid, used }, `trialDay`): the Kit of the Day (`kitOfTheDay()` from the UTC day, kits of level >= `minLevel`) is free for one life once a day whatever your level; any other kit can be rented for one life (`rentPrice`, Gold only). `activeKit()/activeKitId()` (borrowed beats equipped) is what combat, the HUD, the roster pose and the net join use. `used` is set on landing (or when borrowed while already fighting); the borrow ends on an arena death or going back to the lobby after using it (`endBorrowed` in combat.js); an unused one can be returned (rental refunded). UI: the Kit of the Day strip above the list, TODAY/BORROWED badges, the info box's second button (Try free today / Rent 1 life / refund).
- **Juice**: kit-coloured impact sparks + a white flash on your hits, a golden screen-edge flash on your crits (`hud.critFlash`), the kill burst, the swing trail. Sounds `squelch`, `firework`, `zap`, `ultReady`, `ultimate` in audio.js.

## Current state: lobby + arena + combat with kit powers, online with real players (no bots)
The voxel sky-island lobby and the arena are built. The arena is a separate `VoxelWorld` placed straight below the lobby's shaft (`ARENA.floorY` -115), so it is visible down the hole. Falling below `ARENA.enterY` inside the hole starts the drop (`startDrop()` in `main.js`): you keep falling (capped at `ARENA.maxFall`, eased to `softSpeed` over the last `softHeight` m), the sky blends to the arena's starry void below `skyFrom` (`lighting.setVoid`), and touchdown (`land()`) hides + pauses the lobby. Zones in `main.js`: `lobby` -> `drop` -> `arena` -> `dead` (death fade, then `goLobby()` back to spawn; R in the arena does the same). Health (20) is real in the arena: lava burns (`lavaDps`, then `burnTime` of `burnDps`, water puts it out), regen after `regenDelay`; falling below `ARENA.voidY` kills. Dev: `__game.toArena('fire'|'frost'|'summer'|'spring'|'plaza')`, `__game.look(yaw, pitch)`, `__game.combat` (bots, `you`), `__game.hp()`.

**Combat (phase 1, `src/arena/combat.js`, `bots.js`, `weapons.js`, tunables `COMBAT` in config):** free-for-all against arena bots (`COMBAT.bots.count`, fewer on touch) that drop into the plaza with a random kit (level <= `maxKitLevel` and <= the lowest level among the arena's players + `kitLevelAhead` via `botCtx.kitCap`, armor set + weapon from the kit; puppets take the host's kit id from the snapshot), walk the voxels with their own physics (`probe`/`ground` in bots.js: autostep, one-block jumps, swimming, knockback), avoid cliffs/lava/tall walls, chase or circle a target (at most `maxOnPlayer` per player, zombies included; they drop targets they cannot reach), swing on a cooldown or draw and shoot arrows with gravity lead, regen like the player, and die by tipping over + a puff (replaced after `respawn` s). Each kit's main weapon comes from `weaponFor` (bow icons -> bow, axe/mace -> axe, sword/trident/pickaxe -> sword with the kit's art, Bouncer -> knockback stick, Monk -> fists, everything else -> iron sword). The kit weapon sits in hotbar slot 1 (bows: arrow count as the stack size, refilled on each drop); other slots punch. Player: left click / touch sword button = melee (charge meter: damage x(0.2 + 0.8 charge^2), full-charge hit while falling = crit x1.5, sprint hits push harder), hold to draw a bow, release to shoot (aimed where the crosshair meets the world). Damage: armor cuts `armorPerPoint` per kit armor point (max `maxArmorCut`), `iframes` between hits, knockback (player: `knockback()` in player.js). `spawnProtect` s after landing (attacking ends it). **New players** (`COMBAT.rookie`, below its `level`): bot damage x `botDmg` (victim side in `damage()`, so arrows/abilities/zombies too) and at most `maxBots` bots on them (the host reads remote players' `level` from the roster). Kill credit = last hitter within `creditWindow` (also void/lava/fire deaths), assists within `assistWindow`; rewards `COMBAT.rewards` (Gold + XP per kill, streak bonuses, shutdown bonus, and `dmgGold` Gold per hp you deal via `payDamage`: one health bar per target per `dmgGoldWindow` s, relayed hits paid on an armor estimate, none in duels) via state.js; your killstreak resets on death. "In combat" for `combatTag` s after hitting or being hit: R cannot leave the arena. HUD overlay `hud/combatHud.js` + `combat.css` (charge meter, hit marker, status pill, kill banner); sounds `hit`, `bowDraw`, `bowShoot`, `arrowHit`, `killDing`, `streak` in audio.js.

**Kit powers (phase 2): `KIT_POWERS` in config.js, `arena/abilities.js` (ability use + when bots use theirs), `arena/effects.js` (world effects).** Every kit, for the player and for bots alike: passives (speed, jumpMul spring, airJumps ninja double jump, glide, noFall, swimFast, kbResist, dmgTaken, dmg, regen, lifesteal, punchHeal, backstab, lowHpDmg, fallDmg, killHeal, killGold, killStack, revive = phoenix once per life, ghost = invisible after damage, bowSpeed/pierce, cooldownMul), shields (`shield`: hold right click / F / the touch ability button to block hits from the front; viking axes break them for 5 s; `tower` = wider arc), on-hit effects of the kit weapon (ignite, freeze, slow, mark = red arrow through walls, lightning every 3rd hit in a row, swap places) and one ability each (`ability.type`: tnt, snowball, star, orb, potion (cycles harm/slow/heal), firebomb (burning ground), fireball, trident, vines (root), poison (cloud), hook (pull), apple, wall (temporary cobblestone: voxels set in the world + `addFixed` colliders, removed with `removeFixed`), turret, zombies (necromancer minions = bots with `minion`/`owner`; their kills count for the owner, they never respawn), bees, dash, slam, boom (through walls), rewind (3 s of position history)). `ammo` abilities refill on each drop; others have a cooldown. Damage pipeline (`damage()` in combat.js) takes opts (kind, from/dir, kbScale, upScale, noKb, noFlinch for damage over time, ignoreIframes, ignoreShield, pierce, weaponHit); statuses live in `entity.status[key] = until` (slow, freeze, root, invis, mark, speed, shieldBroken); `allies(a, b)` = same entity or owner/summon. Death lines per cause incl. explosion, poison, lightning, magic, sting, fall. **Controls:** F (desktop) / the ability button left of RUN (touch) = kit ability; right click in the arena = block (shield) > use the shop item in hand > kit ability; tapping the selected hotbar slot again uses it (hold for a shop shield). Desktop widget bottom right (`hud.ability`), touch button via `installTouch(...).setAbility`. **Shop items in the arena** (`SHOP_USE`): golden apple (8 hp over 4 s), speed potion (+30 % for 20 s), warp orb (thrown), steak (+8 food), shield (blocks until `durability` hits), XP booster (`state.boostKills`, double XP). **Hunger** (`HUNGER`, arena only, refilled on drop): drains over time and faster when sprinting; below `low` no natural regen and no sprint; the HUD food bar is `hud.setFood`. **Fall damage** (`FALL`): 1 hp per m beyond `safe`, players and bots, skipped by noFall kits and water. Not yet: the scoreboard's "Status" line.

**Online (phase 3): `src/net.js`, `src/remotePlayers.js`, backend `KitRoom.ts` (see its CLAUDE.md for the message list).** `net.js` joins `kitpvp` (Bloxity: `resolveServerEndpoint` or the `?roomId=` launch room via `locateRoom`; dev: `SERVER_URL` = `VITE_SERVER_URL_DEV` or ws://localhost:2567), retries with backoff (offline play meanwhile), reports `updateRoom`, rejoins on a sign-in change; token from `bloxity.getToken()`. main.js sends our pose (`netPose`: position, yaw, pitch, velocity, hp, zone + `combat.netPose()` flags/swing/kit/item) at `NET.poseHz`. `remotePlayers.js` draws the roster (each player on the Bloxity rig in their own look + kit item/shield, no armor, name tag with hp, walk/swing/bow/block poses, invisibility, flames, a kinematic capsule) in the same place as you (lobby vs arena) and exposes them as combat entities (`isRemote`, `key` = sessionId). **Authority:** whoever's client simulates the victim applies the damage. `combat.damage()` on a remote player or a puppet bot relays the raw hit (`hit` / `botHit`, opts via `netOpts`) instead of applying it; statuses / ignite / push / teleport go as `act` (`forwardAct`); heals stay local. Incoming hits run the full pipeline on our side (armor, shields, powers) with the sender resolved by key (`resolveKey`; `stub` when unknown). Every entity has a `key` (`you.key` = sessionId or 'me', bots 'bot:<id>', summons `ownerKey`), and `allies()` compares keys across clients. Deaths: `died` / `botDied` -> the server's `feed` for everyone else and `kill` to a remote killer (who calls `rewardKill`). **Bots:** the host (backend `state.host`) simulates them (`bots.update(..., { simulate, target })`, target = `COMBAT.bots.count` minus the other players in the arena, at least `NET.minBots`) and streams `bots.snapshot()` at `NET.botsHz`; everyone else keeps puppets (`b.puppet`, `applySnapshot`: same id = same seed = same name/kit/skin), and a new host takes its puppets over in place (`takeOver`). Necromancer zombies of a non-host are raised on the host (`summon`). **Effects:** thrown items, arrows, walls (placed for everyone: they collide), turrets, bees, lightning, sonic booms, slams, rewind portals and rebirths are broadcast as `fx` and replayed as ghosts (visual only: `opts.ghost` / ghost arrows never hurt anyone; the owner's client decides what they hit). Testing two clients in one browser: a background tab's game loop pauses, so it stands still and its bots freeze; front the tab you act in. A console `import('/src/x.js')` can return a second copy of a module after HMR; use `__game` (combat, duels, duelWorld, state, hud...) instead.

**Saves, leaderboards, duels (phase 4).** `src/sync.js`: on joining, `progress` replaces the local save with the account's (`state.hydrate`; the account gets its own localStorage key so the guest save survives), `noProgress` new = this browser's progress becomes the account's first save, guest = stays local, error = no saving; every change is sent as `save` (`state.snapshot()`, debounced, + every 30 s). The lobby boards (`holograms.js buildLeaderboards` -> `lobby.setBoards`) draw the server's `leaderboard` (kills / playtime / gold; your own stats while offline); the Duels window shows Top Ranked; the Duels NPC's "N playing" is the roster's duellers + queued (`lobby.setDuelsCount`). **Duels** (`src/duel/`, tunables `DUEL` in config): `world.js` builds `DUEL.slots` + 1 (practice) round platforms (two rows from x0 150; VoxelWorld keys only hold -256..255 per axis) with arena-like lookups; `duels.js` is the controller (queue / cancel / practice / leave, the server's duelStart / duelRound / duelScore / duelEnd, local scoring for practice, rewards `DUEL.rewards` paid when a duel ends, the score bar + countdown overlay `duel.css`). main.js: zone `duel` (fighting like the arena: `damage`, `arenaTick`, combat's `inArena()`), `duels.enter/spawn/exit` hooks (sky = void, spawn pads from `spawnOf`, killY = `DUEL.y - killBelow`), dying in a duel calls `duels.onPlayerDied()` instead of the lobby trip, R = leave (forfeit). combat.js: `combat.duel` (round reset + countdown lock `lockedUntil`, the practice bot via a second bot set on the duel world `practice`, `b.mgr` routes per-bot calls to its set), a composite `world` (arena below `DUEL.minX`, platforms beyond) for arrows and effects, duel deaths skip the kill feed / kill rewards / killstreak, and in a duel the entities are only your opponent. remotePlayers.js draws / targets by area (`areaOf`: lobby, arena or `duel:<id>`).

Three.js (vanilla) + Vite + Rapier. Everything is procedural: block textures, item pixel art, character skins and all sounds (WebAudio synthesis, `src/audio.js`); the only imported model is the Bloxity rig `public/avatars/player.glb`. Font: Fredoka.

- `npm run dev` / `npm run build`. Preview config `kitpvp` (or `kitpvp-kits` on 5243 when 5241 is taken) in `.claude/launch.json` runs vite on port 5241 with `VITE_DEV_MODE=true` (no Bloxity SDK/CDN).
- All tunables in `src/config.js`: identity, `SPAWN`, `PHYSICS` (MC-like 1 m blocks: walk 5.6, jump clears one block, autostep 0.55 for slabs/stairs), `LOBBY` (island radius, pit ellipse + terraces + hole, bot count), `ARENA`, `CRATES`, `DAILY_REWARD`, `KITS` (50 kits from `KIT_TABLE`: id, name, icon art, colour, level, armor points, armor set, desc; Gold price from the level, level 1 kits free; old saves map `knight` -> `swordsman` in `state.js`), `SHOP_ITEMS`, `LOOKS`, `xpForLevel`, plus the look/camera/rig settings from the base.
- **Currency rule**: everything is bought with Gold (earned in the arena, from crates and the daily reward; a fresh save starts with `STARTER` Gold + golden apples). No premium currency anywhere; the reference's "TOP ROBUX" board is "TOP GOLD".

## Files (`src/`)
- `main.js`: boot (SDK -> renderer -> Rapier -> lighting -> lobby -> player -> HUD -> avatar -> loop). Interaction (crosshair ray vs interactable boxes, E key, right click, touch taps, proximity prompt), crate opening + rewards, footsteps/jump/land sounds per surface, fall wind, the arena drop. `__game` (dev) exposes player, scene, lobby, hud, state, teleport, setMode, openCrate, sfx.
- **Voxels** `voxel/`: `blocktex.js` 16x16 pixel painters for every block (Nearest mag, mipmapped min). `voxels.js` block registry (cube, slab, slab_top, stair with facing, fence, cross plants; opaque/cutout/plant), sparse `VoxelWorld`, mesher (face culling + per-vertex AO; 32-cell chunk meshes sharing one texture array per world, see Performance) and greedy cuboid colliders. Also `liquid` (lava/water: surface at 14/16, falls when the same liquid is above; sides only toward non-solid, non-same-liquid cells; non-solid, animated textures repainted by `animateBlocks`), `ladder` (a quad 1/16 off its wall, meta = wall side), `pad` (lily pad over a waterlogged cell), `waterlogged` plants, per-face textures (`tex.px` etc.), `emissive` blocks and **block light**: `bakeLight(extra)` floods light from `light: [color, level]` blocks (lava, glowstone, magma, end gems, chorus flowers) and extra sources (fires, campfire, end rods) and the shader adds it as emission per vertex (only worlds that baked light get the `VOXEL_LIT` shader variant; the lobby does not). **No Z-fighting by construction**: faces against full opaque cubes are dropped, partial shapes skip their shared faces, liquid faces never share a plane with a block face, overlays are strictly larger boxes, props sitting on blocks are lifted a few mm. Keep it that way: never put two visible faces in one plane; offset decals/signs from walls.
- **Arena** `arena/`: `layout.js` places every block in local coords around `ARENA.cx/cz` (y relative to the plaza floor): a square of four quadrants split by 2-wide void seams, a round mud-brick plaza (4 glowstone tiles, half-slab rim open toward the quadrant diagonals, hanging stone cone) bridging them. NW Spring Isles = end-stone islets over the void (fall = death), two purpur towers (pillars, windows, balconies with green end gems, end rods), a giant twisted chorus plant + small ones. NE Summer Valley = terraced grass hills, a river (seagrass, lily pads, a fallen log) that pours off two edges as waterfalls, dark-oak/oak/azalea trees, azalea bushes, flowers, sugar cane, boulders. SW Frost Peaks = snow + frozen lake, giant snow-capped ice spikes with carved arches and floating chunks, a spruce camp with a campfire. SE Fire Lands = netherrack with lava pools (+ a lava fall off the south edge), mounds, magma, crimson roots, fires, and a nether-brick castle (keep with spires, glowstone windows, gate, ladder to the roof, lava basin inside). Returns world-space anchors. `index.js` builds the mesh with baked block light, props (flame planes, campfire, end rods), all emitters (lava pops/embers/smoke, ash, snowfall, ice glints + powder, fireflies, pollen, leaves, river glints, waterfall mist/drops, portal motes, chorus/end-rod sparkles, glowstone motes), animated lava/water, lava/glowstone glow pulse, positional sound sources, and lookups (`biomeAt`, `surfaceAt`, `liquidAt`, `ladderAt`, `groundBelow`) + one-shots (`splash`, `landingBurst`, `burnFx`, `steam`, `voidFx`). Biome names/colours: `BIOMES` in config; the arena sky: `ARENA_SKY`.

- Controls: WASD, Shift sprint, Space jump, mouse look (click grabs cursor), left click attack (hold = draw a bow; touch: the red sword button, drag on it to aim), F kit ability, Q ultimate (touch: ULT), right click / E interact (in the arena right click = block / use item / ability), 1-9 hotbar, K B M L O menus, V first/third person, N day/night, R respawn, Esc closes a menu then opens the portal menu. Never bind P.
- Performance: point lights are expensive on integrated GPUs; the lobby keeps 3 (campfire + 2 lamp posts) and the arena adds none (its glow is baked block light + emissive blocks). The arena is ~63k blocks / ~105k triangles in one mesh; its emitters only run near the player and are scaled down on coarse pointers. Only base skin layers cast shadows.
  - **Static colliders are mirrored into two Rapier worlds** (`physics.js`): Rapier's step costs time per *enabled* collider (moving or not), and the voxels are ~6.5k cuboids (was 3.3 ms per 60 Hz tick; now ~0.2 ms). `addFixed` puts each one in `staticWorld` (never stepped; `segmentClear` ray casts use it, so camera/line-of-sight/aim see everything) and in the stepped `world`, where it is enabled only within 1 cell (8 m cells) of the player (`setStaticFocus`, called in player.js before the controller moves). Remove them with `removeFixed(handle)`, never `world.removeCollider`. Anything new that must collide with static geometry away from the player needs its own focus.
  - **Sun shadow cache** (`shadowCache.js`, installed by `lighting.js`): objects tagged `userData.staticShadow = true` (the lobby / arena / duel voxel meshes, lanterns, chest bodies, the stall chest, the campfire) are drawn into the shadow map only when the shadow box moves, the sun turns or a tagged object is shown/hidden; each frame the cached map is blitted back and only the other casters are drawn over it (hooked into `renderer.shadowMap.render`, so the shadow map is bit-identical to three's). The box stays still until the player drifts 2 m and is snapped to whole shadow texels (`placeSun`). Tag only things that never move; a moving tagged object leaves a frozen shadow. `__game.lighting.shadowCache.enabled = false` = stock pass for A/B. Measured on Intel Iris Plus: lobby frame -34 %, arena -33 %, 351 -> 222 draw calls per lobby frame. On this hardware the lobby is draw-call bound (~0.1 ms per draw), so keep prop draw calls low (e.g. chest boxes use 2 groups, `sideTopBox` in models.js; the 11 lanterns are baked into 4 merged meshes in lobby/index.js: iron, chains, plain bulbs, and the 2 night-lit bulbs whose shared material `lighting.addLamp` drives).
  - Bloom (`postfx.js`) sanitizes its high-pass input (NaN/Inf -> 0, clamp to 64): one bad HDR pixel used to smear into a huge black/white block.
  - **Voxel rendering** (`voxels.js`): `buildMesh()` returns a Group of `CHUNK` (32) cell chunks so the camera and the sun's shadow pass frustum-cull them. Every block texture is a layer of one sRGB `DataArrayTexture` per world (same filtering as `blockTexture`); a block's layer / roughness / glow are the `bdata` vertex attribute, so a chunk draws at most 4 times (solid, water, cutout, plant materials; cutout + plant are a second mesh with a texture-array `customDepthMaterial` so leaf shadows keep their holes). Lava / glowstone pulse through `setBlockGlow(tex, intensity)` (one uniform), animated lava / water frames reach the arrays via `onBlockRepaint` in blocktex.js. Measured vs the old single mesh with one material per texture (9 views): draw calls -6..-59 %, triangles -9..-52 %, pixels identical (<= 0.012 % differ by > 8/255). New block materials: never per-texture `MeshStandardMaterial`s for world blocks; add the texture to the world and its data to `bdata`.
- Boxity layout: Boxity draws the toolbar + chat top-left; the HUD stays out of those rectangles.

## Mobile & responsive (required for every change)
The game must play on phones and tablets (portrait and landscape) as well as desktop. Treat a feature as unfinished until it works on touch and on a small screen.
- **Input**: every action needs a touch path, not just a key. Use Pointer Events (`pointerdown/move/up`, check `e.pointerType`), never mouse-only events. Layout (implemented in `src/touch.js`): left-thumb virtual joystick -> `inputState.move`, right-side drag -> `inputState.look`, on-screen buttons for jump/sprint/mode/etc., pinch -> `inputState.zoom`. Everything still feeds `inputState` in `src/input.js` so game code stays input-agnostic. Pointer lock does not exist on touch; never rely on it.
- **Detection**: decide touch UI with `matchMedia('(pointer: coarse)')` / `navigator.maxTouchPoints`, not the user agent. Show touch controls only on coarse pointers; a device can have both.
- **Layout/UI**: HUD and menus use relative units (`%`, `vw/vh`, `dvh`, `clamp()`) and flexbox/grid, no fixed pixel layouts. Tap targets >= 44px. Respect notches with `env(safe-area-inset-*)` (viewport already has `viewport-fit=cover`). Text readable at 360px width. No hover-only interactions. Add `touch-action: none` on the canvas and game controls so the browser does not scroll/zoom.
- **Resize/orientation**: anything sized to the screen (camera aspect, renderer, HUD) must react to `resize` (covers orientation changes). Use `visualViewport` where the on-screen keyboard or browser bars matter.
- **Performance**: mobile GPUs are weak. Respect the `graphics_quality` presets in `src/config.js` (cap DPR, shadow map size, draw distance); default to a lower preset on coarse-pointer devices. Avoid per-frame allocations; keep draw calls and texture sizes low.
- **Testing**: check every UI/input change at a phone viewport (e.g. 375x812 and landscape 812x375) with touch emulation, plus desktop, before calling it done.
- **Touch layout (block-game phone style)**: translucent square buttons. Bottom-left: floating joystick, or a D-pad (Opts > "Move with", `state.settings.dpad`; arrows, forward diagonals while forward is held). Bottom-right 2x2 arc: jump (corner), attack left of it, RUN above jump, kit ability above attack. A quick tap on the look area = talk to what is under the finger, or a melee hit in the arena / a duel. Top utilities: camera, day/night, respawn. Landscape: menu squares in a row at the top-right, left of the utilities; hotbar + bars bottom-centre between the pads. Portrait (`#hud.portrait`, height > 1.15 x width): a right-hand column under Boxity's strip = [menu] (the menu squares open as a row to its left, `.menu-open`; it carries their "!") + the utilities; hotbar on the bottom edge and the controls stand on it (hud.js publishes `--hud-ctl-b`, `--hud-top-safe`, `--hud-right-safe` on :root for touch.css). The scoreboard starts folded to its title on touch (tap to open). Portrait widens the vertical FOV (`portraitFov` in camera.js) and shrinks the held item (viewmodel.js) so the view is not a tunnel.
